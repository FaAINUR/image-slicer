# Image Slicer

Графическое приложение на Rust для нарезки спрайтшитов и других
изображений на отдельные PNG-файлы.

Позволяет проверить границы нарезки до сохранения, увеличить
изображение и объединить несколько соседних клеток в один спрайт.

## Возможности

- Выбор изображения через файловый диалог.
- Настройка ширины и высоты базовой клетки.
- Предпросмотр границ нарезки поверх исходного изображения.
- Масштабирование от 10% до 800%.
- Горизонтальная и вертикальная прокрутка.
- Шахматный фон для просмотра прозрачности.
- Выделение клеток мышью.
- Объединение соседних клеток в прямоугольную область.
- Разъединение выбранной области.
- Сохранение обычных и объединённых областей в PNG.
- Сохранение в отдельную подпапку для каждой нарезки.
- Фоновый экспорт без блокирования интерфейса.

## Предпросмотр

Цвета границ помогают различать области:

| Цвет | Значение |
|---|---|
| Зелёный | Обычные клетки нарезки |
| Жёлтый | Выделенные клетки |
| Синий | Объединённая область |

Рамки, подсветка и шахматный фон отображаются только в интерфейсе.
В сохранённые PNG они не попадают.

## Статус проекта

Приложение разработано и проверено на Arch Linux.

Для Arch Linux подготовлен локальный пакет.
Сборка и установщик для Windows требуют отдельной проверки.

Понадобятся Rust, Cargo и системные компоненты графической среды.

```sh

```

Запуск через Cargo:

```sh

```

Запуск собранного приложения на Linux:

```sh
./target/release/image_slicer
```

## Как пользоваться

1. Нажмите «Выбрать изображение».
2. Укажите ширину и высоту базовой клетки.
3. Проверьте зелёные границы на предпросмотре.
4. При необходимости увеличьте изображение кнопкой «+»
   или ползунком масштаба.
5. Если один спрайт занимает несколько клеток, выделите их
   щелчками мыши.
6. Нажмите «Объединить выбранные».
7. При необходимости выберите папку результата.
8. Нажмите «Нарезать и сохранить PNG».

### Объединение клеток

Объединять можно только клетки, которые полностью заполняют
прямоугольник, без промежутков и пропусков.

Например, при базовой клетке 32 × 32:

- две клетки по горизонтали → один PNG 64 × 32;
- три клетки по вертикали → один PNG 32 × 96;
- четыре клетки в области 2 × 2 → один PNG 64 × 64.

Клетки внутри объединённой области отдельно не сохраняются.

Жёлтое выделение само по себе не создаёт объединение:
его необходимо подтвердить кнопкой.

### Разъединение

1. Щёлкните по синей объединённой области.
2. Нажмите кнопку разъединения в панели настроек.

Чтобы удалить все объединения, используйте кнопку их сброса.

## Результат сохранения

Для каждой нарезки создаётся новая подпапка:

```text
spritesheet_tiles/
├── slice_0001/
│   ├── tile_00000_x0_y0.png
│   ├── merged_00001_x32_y0.png
│   └── ...
└── slice_0002/
    └── ...
```

Если папка результата не выбрана, приложение создаёт каталог
рядом с исходным изображением.

Имена файлов содержат координаты левого верхнего угла области
в исходном изображении.

## Установка в Arch Linux

В проекте есть локальный рецепт упаковки:

```text
packaging/arch/PKGBUILD
```

Сначала соберите приложение и подготовьте бинарник:

```sh
cargo build --release --locked
cp target/release/image_slicer packaging/arch/image-slicer
```

Затем соберите пакет:

```sh
cd packaging/arch
makepkg -f
```

Установите полученный пакет через `sudo pacman -U`,
указав его точное имя.

Для версии 0.2.0 с релизом пакета 1:

```sh
sudo pacman -U ./image-slicer-0.2.0-1-x86_64.pkg.tar.zst
```

Запуск установленного приложения:

```sh
image-slicer
```

`makepkg` запускается без `sudo`.

Рецепт предназначен для локальной упаковки.
Перед распространением на другие системы необходимо проверить
полноту зависимостей.

## Ограничения

- Сетка начинается в левом верхнем углу изображения.
- Отступы и промежутки между клетками пока не настраиваются.
- Объединять можно только прямоугольные области.
- Изменение размера клетки сбрасывает объединения.
- Загрузка другого изображения сбрасывает объединения.
- Объединения не сохраняются между запусками.
- Автоматического распознавания спрайтов нет.
- Надписи и другие элементы исходника тоже могут попасть в нарезку.
- Крайние кусочки будут меньше заданного размера, если изображение
  не делится на сетку без остатка.
- Для очень больших изображений детализация предпросмотра может
  быть уменьшена; экспорт использует исходное изображение.
